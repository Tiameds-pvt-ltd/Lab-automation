# AGENTS.md - TiaMeds Lab Automation

**Purpose**: Guide AI agents to be immediately productive in this multi-service healthcare backend ecosystem.

## Big Picture Architecture

### Two Distinct Microservices
1. **Lab-automation** (Spring Boot 3.3.4, Java 17): Core lab management system handling patient testing workflows
2. **pharma-aggregator-server** (Spring Boot 4.0.1, Java 21): Pharmacy marketplace for sellers and products

Both use PostgreSQL, JWT auth (JJWT), AWS S3, and are containerized for AWS ECS Fargate deployment.

### Key Data Flows

**Lab-automation Flow:**
- Users authenticate via JWT → Spring Security filters validate tokens and IP whitelist
- Audit Aspect (`@Auditable` annotation) automatically tracks entity field changes in `LabAuditLogs` table
- Lab technicians create Patients → Visits (appointments) → Samples → Tests (with reference ranges)
- Reports generated as JSON with test results, routed through S3 for CDN delivery
- Rate limiting via `Bucket4j` prevents brute force; password reset uses DB-backed rate limits

**Pharma-aggregator Flow:**
- Sellers register (temporary staging table `TempSeller`) → admin approval → permanent `Seller` table
- Product import via Excel using Strategy pattern: `ProductImportStrategy` (abstract) with concrete implementations per category (Drug, Consumable, Supplement, Cosmetic, FoodInfant, NonConsumable)
- Each import strategy handles category-specific field validation and database insertion

### Why This Structure Exists
- **Lab-automation**: Audit compliance critical for healthcare; rate limiting prevents credential-stuffing attacks
- **pharma-aggregator**: Strategy pattern enables flexible product categorization without repeating import logic

## Project-Specific Conventions

### 1. Environment Configuration Strategy
- Base config in `application.yml` (shared across all profiles)
- Profile-specific overrides in `application-{dev,test,prod}.yml`
- Runtime activation via `SPRING_PROFILES_ACTIVE` environment variable (required for ECS Fargate)
- All sensitive values (DB credentials, JWT keys, AWS credentials) injected as env vars, NOT in code

**Example lab-automation config structure:**
```yaml
# application.yml (base)
server.servlet.context-path: /api/v1
spring.jpa.hibernate.ddl-auto: update

# application-prod.yml (override)
spring.jpa.hibernate.ddl-auto: validate  # No auto-schema update in prod
logging.level.org.springframework: WARN   # Less noise in production
```

### 2. JWT Implementation Details
- **Lab-automation**: RS256 algorithm with private/public keys (asymmetric)
  - Access token: 15 minutes
  - Refresh token: 1 day
  - Encrypted subject field for additional security
  - Stored in cookies with domain `.tiameds.ai`, SameSite=None (for cross-domain APIs)

- **pharma-aggregator**: Similar JWT but simpler; no subject encryption
  - See `AuthTokenFilter` for validation logic

**Key file**: Both projects use custom JWT utility classes (not auto-generated by JJWT). Extract JWT claims manually.

### 3. Security Model (Lab-automation)

**Roles & Permissions** (`SpringSecurityConfig.java`):
- ADMIN, TECHNICIAN, DESKROLE, SUPERADMIN
- Assigned per User entity
- Enforced via `@PreAuthorize("hasRole('ADMIN')")` annotations

**Rate Limiting**:
- **Login attempts**: 5 attempts per 10 minutes (in-memory via Bucket4j)
- **Password reset emails**: 3 per hour per email, 3 per hour per IP (database-backed for distribution)
- **Onboarding tokens**: 3 verification emails per hour per email

**IP Whitelist** (optional, disabled by default):
- Controlled by `security.ip.whitelist.enabled` config
- If enabled, only whitelisted IPs can access /api/v1 endpoints

### 4. Audit Logging (Lab-automation Only)

Use `@Auditable` annotation on entity fields to auto-track changes:
```java
@Entity
public class Patient {
    @Id private Long id;
    @Auditable private String name;  // Changes logged automatically
}
```

Aspect (`AuditAspect.java`) intercepts updates, extracts old/new values, creates `LabAuditLogs` records. Useful for compliance audits and debugging data corruption.

### 5. External Integrations

**AWS S3** (both projects):
- Configured via environment vars: `AWS_REGION`, `AWS_S3_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`
- Lab-automation uses presigned URLs (valid for 10 minutes by default) for secure file uploads
- `S3StorageService.generatePresignedUrl()` generates temporary download links

**Email** (both projects):
- Gmail SMTP (credentials in env vars `SPRING_MAIL_USERNAME`, `SPRING_MAIL_PASSWORD`)
- Subject to Gmail app password restrictions (not regular password)

**SMS** (pharma-aggregator only):
- Twilio SDK (`TwilioConfig.java`)
- Account SID and Auth Token in env vars

**PDF Generation** (pharma-aggregator only):
- iText 7.2.5 for creating reports
- `PdfService.java` handles layout and content

**Excel Import/Export** (pharma-aggregator only):
- Apache POI 5.2.5
- Product import via strategy classes (`ProductImportStrategy` and subclasses)

### 6. Database Patterns

**Hibernate Configuration** (Lab-automation):
```yaml
hibernate.jdbc.batch_size: 15          # Batch inserts/updates
hibernate.order_inserts: true          # Order batch operations
hibernate.default_batch_fetch_size: 10 # Batch fetches for collections
```
Improves performance; when modifying queries, be aware batching may reorder operations.

**Connection Pooling** (Lab-automation):
- HikariCP with pool size 40 (production-grade)
- `open-in-view: false` (best practice; prevents lazy-loading in views)

**Database Versioning** (pharma-aggregator):
- Flyway migrations in classpath (auto-applied on startup)

**Schema Changes** (Lab-automation):
- Documented in `/Document/database_migration_*.sql` files
- Manual review required before applying

### 7. API Contract Conventions

**Context Path**: `/api/v1` for both projects
**Response Format**: REST JSON
**Swagger/OpenAPI**:
- Lab-automation: `/doc` → `springdoc-openapi 2.6.0`
- pharma-aggregator: `/swagger-ui` → `springdoc-openapi 2.3.0`

Generate API docs from annotations:
```java
@GetMapping("/{id}")
@Operation(summary = "Get patient by ID", tags = {"Patients"})
@ApiResponse(responseCode = "200", description = "Patient found")
public Patient getPatient(@PathVariable Long id) { ... }
```

### 8. Exception Handling

**Lab-automation**: Custom exceptions at `services` layer; no global handler (relies on Spring defaults)

**pharma-aggregator**: `GlobalExceptionHandler.java` with `@RestControllerAdvice`:
- `BaseException` → 400 Bad Request
- `ResourceNotFoundException` → 404 Not Found
- `ValidationException` → 422 Unprocessable Entity

When implementing new exceptions in lab-automation, follow pharma-aggregator pattern for consistency.

### 9. Product Import Strategy Pattern (pharma-aggregator)

**Location**: `src/main/java/com/example/pharmaaggregatorserver/service/product/util/`

**Abstract class**: `ProductImportStrategy` defines `importProduct(ExcelRow row)` method
**Concrete implementations**:
- `DrugImportStrategy`: Validates drug-specific fields (batch, expiry, dosage)
- `ConsumableImportStrategy`: Different validation rules
- Similarly for Supplement, Cosmetic, FoodInfant, NonConsumable

**When adding new product categories**:
1. Create new class extending `ProductImportStrategy`
2. Implement category-specific validation in `importProduct()`
3. Register in factory/controller that routes based on category

## Integration Points & External Dependencies

### Critical Files for Cross-Component Communication

| Component | File | Purpose |
|-----------|------|---------|
| JWT Auth | `JwtFilter.java` (lab) | Validates every request; calls `SecurityContextHolder.getContext().setAuthentication()` |
| Audit | `AuditAspect.java` (lab) | Intercepts service method calls on `@Auditable` entities |
| Rate Limit | `RateLimitFilter.java` (lab) | Blocks requests if user/IP exceeds thresholds |
| IP Whitelist | `IpWhitelistFilter.java` (lab) | Blocks requests from non-whitelisted IPs |
| S3 Upload | `S3StorageService.java` (both) | Called by report/product services to upload files |
| Email | `EmailService.java` (both) | Called by auth/registration/reset password flows |
| Product Import | `ExcelProductImportController.java` (pharma) | Routes file to strategy based on product category |

### When Things Break

1. **JWT token invalid/expired**: Check `security.jwt.public-key-location` and clock skew
2. **S3 upload fails**: Verify AWS credentials in env vars and bucket permissions
3. **Email not sent**: Check `SPRING_MAIL_*` credentials and "Allow Less Secure Apps" setting in Gmail
4. **Audit logs not created**: Verify `@Auditable` annotation presence and AOP is enabled (`spring-boot-starter-aop`)
5. **Rate limiting bypassed**: Ensure filter is registered in `SpringSecurityConfig` filter chain

## Common Developer Workflows

### Adding a New Endpoint (Lab-automation)

1. **Create Controller** in appropriate package (`controller/lab/`, `controller/auth/`, etc.)
2. **Add Service Method** handling business logic
3. **Apply Security Annotations**: `@PreAuthorize("hasRole('...')")` if role-restricted
4. **Add Swagger Annotations**: `@Operation`, `@ApiResponse` for OpenAPI docs
5. **Test**: Manually via Postman (tests skipped in pom.xml); verify JWT works

```java
@RestController
@RequestMapping("/api/v1/patients")
@PreAuthorize("hasRole('TECHNICIAN')")
public class PatientController {
    @PostMapping
    @Operation(summary = "Create patient")
    public Patient createPatient(@RequestBody PatientDTO dto) { ... }
}
```

### Adding a New Entity with Audit Logging

1. Create entity class in `entity/` package
2. Add `@Entity`, `@Table`, `@Id`, etc.
3. Mark fields to track with `@Auditable`
4. Ensure `AuditAspect` is enabled (check application.yml for AOP config)

```java
@Entity
@Table(name = "patients")
public class PatientEntity {
    @Id @GeneratedValue private Long id;
    @Auditable private String name;  // Auto-tracked
    private String notes;              // NOT tracked
}
```

### Deploying to AWS (Both Projects)

1. **Build locally**: `mvn clean package -DskipTests`
2. **Build Docker image**: `docker build -t aws-account-id.dkr.ecr.region.amazonaws.com/tiameds-lab:latest .`
3. **Push to ECR**: `docker push ...`
4. **Update ECS task definition** with new image URI and env vars (DB_URL, DB_USERNAME, DB_PASSWORD, SPRING_PROFILES_ACTIVE, etc.)
5. **Update ECS service** to deploy new task revision

See `/Document/deploymentguideline.md` (lab-automation) for full AWS infrastructure setup.
